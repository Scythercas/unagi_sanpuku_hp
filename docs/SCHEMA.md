# microCMS スキーマ定義書

Hobby プラン（API 5 個上限）ちょうどで確定。**形式（オブジェクト/リスト）は作成後に変更しづらい**ため、この定義どおり作成すること。フィールド ID は API レスポンスのキーになる（英字）。表示名は管理画面での日本語ラベル。

セレクトの選択肢は初回に確定する（後から変えると既存データの整合が崩れる）。並び順は `order`（数値）で制御する（microCMS 既定は作成日時順のため）。価格は数値・税込に統一し、「円」表記や桁区切りはコード側で整形する。

---

## API① `shop` — 店舗基本情報（**オブジェクト形式**）

「まず変わらない単一情報」を 1 レコードに集約。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `name` | 店名 | テキスト | ○ | |
| `catchcopy` | 一言紹介 | テキストエリア | | 開発者がドラフト→店主確認 |
| `hours` | 営業時間 | テキストエリア | ○ | ランチ/ディナー・曜日別を改行で |
| `closedDays` | 定休日 | テキスト | ○ | |
| `address` | 住所 | テキスト | ○ | |
| `tel` | 電話番号 | テキスト | ○ | コード側で `tel:` リンク化 |
| `parking` | 駐車場 | テキストエリア | | 「あり（5台）」等、有無＋補足 |
| `seatsCounter` | カウンター席数 | 数値 | | |
| `seatsTable` | テーブル席数 | 数値 | | |
| `takeout` | テイクアウト対応 | 真偽値 | | |
| `delivery` | 出前対応 | 真偽値 | | |
| `instagramUrl` | Instagram URL | テキスト | | |
| `accessNote` | アクセス補足 | テキストエリア | | 最寄り駅・バス等（任意） |
| `notes` | その他ご案内 | テキストエリア | | 支払い方法・予約方法等。改行区切りで複数行可 |
| `heroImage` | トップの写真 | 画像 | | 1画面目に使う写真。未設定ならギャラリーの「調理」で代替 |
| `ownerMessage` | 店主の言葉 | テキストエリア | | 味付けの経緯・おすすめの食べ方等。空ならセクション非表示 |

地図はコード側に iframe 固定。緯度経度を CMS に持たせる必要はない。

## API② `menu` — メニュー（**リスト形式**）

1 品＝1 レコード。松竹梅は品名で表現（例「うな重 松」）。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `category` | カテゴリ | セレクト | ○ | 下記選択肢 |
| `name` | 品名 | テキスト | ○ | |
| `price` | 価格 | 数値 | ○ | 税込に統一 |
| `description` | 説明 | テキストエリア | | 任意 |
| `image` | 写真 | 画像 | | 任意。品ごとの写真はここ |
| `order` | 表示順 | 数値 | ○ | 昇順で描画 |
| `isFeatured` | おすすめ | 真偽値 | | 写真付きで大きく見せる代表の品。5品程度に絞る |

`isFeatured` は写真主体デザイン（`feature/design-photo`）向けの追加フィールド。未作成の場合は「写真がある品を先頭から5品」→「ドリンク以外の先頭5品」の順に自動で代替するため、作らなくてもサイトは壊れない。

`category` の選択肢（この順で表示グルーピング）：
`うな丼` / `うな重` / `定食` / `一品` / `宴会・コース` / `テイクアウト` / `ドリンク`

実店舗の品書き（お品書き写真）確認により、蒲焼定食・上蒲焼定食・上白焼定食・刺身定食・豚角煮重などの「定食」枠が既存の6分類に収まらないため追加した。`宴会・コース` `テイクアウト` は現時点で具体的な品目が未確認のため、確認が取れるまで空でよい（空カテゴリは非表示になる）。

**⚠️ microCMS 管理画面で `category` を作成する際は必ず「単一選択」にすること。** 「複数選択」で作成すると API 応答が配列（例 `["うな重"]`）になる。実装側（`src/lib/microcms.ts` の `firstOf()`）は配列で返っても先頭要素だけを採用して壊れないようにしているが、2つ以上選んだ場合は2つ目以降が無視されるため、意図しないデータ落ちに気づきにくい。

## API③ `gallery` — 写真ギャラリー（**リスト形式**）

「見せる用の写真集」。メニュー写真とは役割を分ける。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `image` | 画像 | 画像 | ○ | |
| `type` | 種別 | セレクト | ○ | 下記選択肢 |
| `caption` | キャプション | テキスト | | 任意 |
| `order` | 表示順 | 数値 | ○ | 昇順で描画 |

`type` の選択肢：`外観` / `内装` / `調理` / `料理` / `その他`

`category` と同様、**必ず「単一選択」で作成すること**（複数選択時の挙動は上記参照）。

## API④ `recruit` — バイト募集（**オブジェクト形式**）

`isOpen` で募集セクションの表示/非表示を切り替える（古い募集が残る事故を防止）。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `isOpen` | 募集中 | 真偽値 | ○ | false のときセクションごと非表示 |
| `jobDescription` | 仕事内容 | テキストエリア | | |
| `wage` | 給与・時給 | テキスト | | |
| `shift` | 勤務時間・シフト | テキストエリア | | |
| `howToApply` | 応募方法・連絡先 | テキストエリア | | 「まずはお電話ください」等 |

## API⑤ `news` — お知らせ（**リスト形式**）

臨時休業・繁忙期営業案内・イベント等。最頻更新。空ならセクション非表示。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `title` | タイトル | テキスト | ○ | |
| `body` | 本文 | リッチエディタ | ○ | |
| `publishedAt` | 公開日 | 日時 | ○ | |
| `important` | 重要 | 真偽値 | | 臨時休業を目立たせる（任意） |

## 実装側の扱い（要点）

- 一覧（`menu`/`gallery`/`news`）は取得後 `order`（`news` は `publishedAt`）でソート。
- 画像フィールド（`menu.image`・`gallery.image`・`shop.heroImage`・`shop.ownerImage`）は**ビルド前にローカル取得**して最適化（`CLAUDE.md` の画像パイプライン契約）。
- **⚠️ 画像フィールドを新設したら、必ず `scripts/prebuild-images.mjs` の取得対象にも追加すること。** ここに漏れると、その画像だけ microCMS の URL が最終 HTML に残り、訪問者のアクセスが 20GB/月 の転送枠を直接消費する（不変条件1違反）。
- `recruit.isOpen === false` → 採用セクション非表示。`news` 空 → お知らせ非表示。`shop` の任意項目が空なら該当行を出さない。
- ビルド用 API キーは **GET 専用**に絞る。
- Webhook 通知タイミングは「公開・更新／非公開」時のみ（下書き保存では再ビルドしない）。
